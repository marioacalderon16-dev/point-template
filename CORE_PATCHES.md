# Parches al core de point

Origen: copiado de una API en producción con `php point init` el 2026-09-23.
Cada parche va en un commit con prefijo `core:`.

| # | Archivo | Descripción |
|---|---|---|
| 1 | core/Endpoint.php (sendResponse) | Envía `status` entero del array como código HTTP; 204 sin cuerpo |
| 2 | core/Endpoint.php (sendResponse) | Handler que devuelve string → `text/plain` (verify de Meta) |
| 3 | core/Endpoint.php (run) | `expects` conserva campos con source `middleware` (`_user_id`, `_user`) |
| 4 | core/Endpoint.php (run) | Middlewares globales solo en index.php (antes corrían 2 veces) |
| T | bootstrap.php, point (runTests) | `POINT_TESTING=1` carga rutas de `tests/fixtures/endpoints` solo en `php point test` |
| 5 | point (requireApp, work, dbSql) | `work*` cargan bootstrap (POINT_NO_ROUTES); `--max-jobs`, `--max-time`, SIGTERM/SIGINT; nuevo `db:sql <archivo>|--all [--force]` con tabla `_sql_migrations` |
| 6 | core/Queue.php (processNext, execute) | Reclamo atómico del job con `rename(.processing)` |
| 7 | core/QueryBuilder.php (connection, insertReturning) | `DB_EMULATE_PREPARES` por env; `insertReturning()` con RETURNING |
| 8 | bootstrap.php | `safeLoad()` (sin .env obligatorio) y `$_ENV` completado desde `getenv()` para contenedores |
| 9 | core/Middleware/RateLimitMiddleware.php, point (runTests) | Contadores en archivo con flock y 256 shards (sin tabla `rate_limits`), tope `RATE_LIMIT_MAX_FILES`, `peek()`, `purgeExpired()` (scheduler), bucket overflow, modo estricto (fail-closed en auth) y limpieza por `reset` (ventanas de hasta 1 día), clave de usuario como cadena (UUID), 429 `{status,message,retryAfter}`, IP con TRUSTED_PROXIES (CIDR, XFF de derecha a izquierda); `RATE_LIMIT_DIR` aislado por corrida de tests |
| 10 | point (dbSql) | En Postgres crea (`CREATE SCHEMA IF NOT EXISTS`) el primer esquema del `search_path` antes de `_sql_migrations`: con `options='--search_path=x'` en una base nueva fallaba con "no schema has been selected to create in". Test con cluster Postgres efímero (sin binarios de Postgres el test no comprueba nada) |
| 11 | core/Endpoint.php (run) | `APP_STRICT_MODE` se parsea con `FILTER_VALIDATE_BOOLEAN` (el texto `'true'` daba `TypeError` en el Validator bajo strict_types: 500 en todo endpoint con `expects`); en modo estricto los campos del cuerpo no declarados → 422 **antes** de que `expects` los filtre (antes nunca se rechazaba ninguno) |
| 12 | bootstrap.php | Las variables del entorno del proceso tienen prioridad sobre `.env`: el bucle `getenv()` → `$_ENV` va antes de `Dotenv::safeLoad` (inmutable). Antes `.env` las pisaba y los tests con otra base o secreto acababan usando los del `.env` |
| 13 | point (init) | `JWT_SECRET` del `.env` generado ya no queda como `<hex>"change-me"` (regex sobre la línea completa); copia `composer.json`/`composer.lock`/`phpstan.neon` de la plantilla (php ^8.4, `listeners/`, phpstan; el Dockerfile copia el lock); deja de copiar `database/config.php` y `.htaccess` de la raíz (no existen); copia `endpoints/health.php`, `scheduler`, `config/schedule.php`, `public/` (con `.htaccess`), `Dockerfile`, `railway.json` y `docker/`, e instala y habilita los plugins `health` y `scheduler` de los que dependen |
| 14 | core/Testing.php (http) | Usa solo `http_get_last_response_headers()` (PHP ≥ 8.4): la mera referencia a `$http_response_header` emitía una deprecación en PHP 8.5 en cada `php point test` |
| 15 | scribe | Lee `DB_DSN`/`DB_USER`/`DB_PASS` de `$_ENV` (antes `require database/config.php`, archivo ya eliminado: `scribe` y `point migrate|rollback|seed|make:migration|make:seed` daban fatal). Misma precedencia que bootstrap.php (parches 8 y 12): entorno del proceso primero y `.env` opcional con `safeLoad()`; sin `DB_DSN` sale con código 1 y mensaje claro. Test con sqlite en un directorio temporal |
| 16 | point (createTest) | Nuevo `make:test <nombre>`: crea `tests/<nombre>_test.php` (nombre en minúsculas, sin `_test` duplicado) con un test de ejemplo contra `/health`; falla si ya existe |
| 17 | config/middleware.php, core/Middleware/MiddlewareManager.php, core/Endpoint.php (run), bootstrap.php, point (runTests) | Seguridad: `make:endpoint` usa por defecto el grupo `protected`, que no estaba declarado, y un grupo inexistente no aplicaba ningún middleware (el endpoint quedaba abierto sin token). Ahora `protected` = `[auth]` y `public` = `[]` en la config, los grupos se declaran aunque estén vacíos (`defineGroup`/`hasGroup`) y un grupo no declarado lanza excepción (500, falla cerrado). `php point test` carga el entorno como bootstrap (proceso y luego `.env`) y, sin `JWT_SECRET` válido, usa uno aleatorio por corrida, así `Auth::issue()` en un test firma con el secreto que verifica el servidor |
| 18 | .dockerignore, point (init) | `.dockerignore` en la plantilla y copiado por `init`: el `COPY . .` del Dockerfile metía `.env` (secretos), `.git`, `tests/` y `vendor/` de desarrollo en la imagen al construir en local |
| 19 | .github/workflows/ci.yml, point (init) | `init` copia el CI a los proyectos nuevos. El CI levanta un Postgres desechable (`services: postgres:18`), pasa `DB_DSN`/`DB_USER`/`DB_PASS` como variables del proceso y ejecuta `php point migrate` antes de los tests: los tests de un proyecto nunca tocan la base de desarrollo ni la de producción. `actions/checkout@v5` (v4 usaba Node 20, retirado) |
| 20 | point (init) | `init` crea `.gitkeep` en `middlewares`, `services`, `jobs`, `listeners`, `database/migrations` y `database/seeds`: git no guarda carpetas vacías, así que en un clon (CI) faltaban rutas de `phpstan.neon` y `composer stan` fallaba con "Path .../services does not exist". Test: clona el proyecto generado y comprueba todas las rutas de phpstan.neon |
| 21 | point (runTests), .env.example, docs/GUIA_INICIO.md | `php point test` carga `.env.testing` (opcional) antes que `.env` y exporta sus variables al servidor de test y a scribe; si define `DB_DSN`, migra esa base antes de los tests. Sin él, avisa de que los tests escriben en la base de desarrollo. El entorno del proceso sigue mandando (en CI no cambia nada) |
| 22 | railway.json, docs/GUIA_INICIO.md | Migraciones automáticas al desplegar: `deploy.preDeployCommand` = `php /var/www/html/scribe migrate` (ruta absoluta: Railway no documenta el directorio de trabajo; scribe resuelve todo con `__DIR__`). Corre en un contenedor aparte con las variables del servicio antes de arrancar la versión nueva; si falla, el despliegue no continúa |
| 23 | Dockerfile, .github/workflows/ci.yml, docs/GUIA_INICIO.md | La imagen Docker instala también `pdo_mysql` (antes solo `pdo_pgsql`: un proyecto MySQL desplegado con Docker fallaba con "could not find driver").
